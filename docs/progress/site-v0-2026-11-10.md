# Project website v0, 10 November 2026

A static website for the project, in `site/`, built with Astro 7.3.8 and
Starlight 0.42.8 and deployed to GitHub Pages
(`https://zhuowcui.github.io/open-ui/`) by `.github/workflows/site.yml`.
Plan workstream E (brand and web presence) and D (docs infrastructure). It
changes no engine, framework or components source.

## Direction

The first draft led with evidence: Chromium versions, census numbers, PR
links and a pixel-diff slider. The user rejected it as hard to read and not
about the product. This version is written for app developers choosing a
framework, after a study of Tauri, Flutter, Slint, Dioxus, Zed, shadcn/ui
and Bun. The home page answers, in order: what Open UI is, what its apps
look like, how it feels to write, what you get, and how to start. Fidelity
is one compact section, with the method on a short docs page.

## What could not be rendered, and the workaround

- **`Card` and column flex.** A column flex container lays out each text
  item as if at its min-content width, so items grow tall (the components
  track's C4 finding). `Card` is a column flex box and its header is a grid
  with an `auto` column, so cards rendered far taller than shadcn/ui's. The
  scenes use block flow and row flex instead, with a bordered panel built
  from styled elements; the components page says why.
- **Icons in the app.** Open UI's SVG images support only static shapes and
  axis-aligned paths, so Lucide icons (curves) are not drawn in the
  screenshots; the dashboard uses text, counts and initials. The site's own
  icons are HTML.
- **No `flex` shorthand** and no `box-shadow` literal in `style:`; the
  scenes use `flex-grow`/`flex-basis` and no shadows.

### Findings while writing the reference (behavior on main)

These are documented on the element and concept pages as gaps; none was
changed, since the site track does not edit engine or framework source.

- No user-agent stylesheet: every element starts from CSS initial values.
- An unknown tag compiles, then panics with `UnknownTag` when built.
- A boolean attribute is present whatever its value (`disabled={false}`
  disables).
- The mouse sends no `pointer*` events; `click` fires for any button;
  `dblclick`, `contextmenu`, `mouseover`, `toggle` and `submit` are never
  sent.
- `text-decoration` underline is not drawn on inline elements.
- `textarea` ignores padding for its text and draws the placeholder in the
  text color.
- `select` has no popup and draws its options over each other.
- `progress` ignores `max`; `meter` ignores `low`, `high` and `optimum`;
  checkbox, radio, range, meter and progress are 0×0 unless sized.
- `details` toggles on click only, fires `input` and `change` on the
  `<details>`, and has no marker.
- `img` loads nothing from `src`; images are registered as bytes.
- `list-style` accepts only `none` and `disc`.

### The name: Div

The user named the framework Div and owns `div.build`. The site is branded
Div (wordmark, titles, Starlight title, Open Graph tags, footer) and the
"working name, unrelated to the W3C Open UI group" notes are gone. It is
served at the domain root: `public/CNAME` is `div.build`, Astro's `site` is
`https://div.build` and `base` is `/`, and the dev server is at
`http://localhost:4321/`. The name, domain and repository URL are set once,
in `site/src/lib/project.mjs`.

Code is not renamed: crates are `openui-*`, the CLI is `openui` and the
repository is `zhuowcui/open-ui`, so every sample and command stays as on
`main`, and Getting started says the packages and CLI keep the `openui`
name while the rename lands. Four renders show the name and were redrawn:
`settings-light.png`, `settings-dark.png`, `docs-el_details-light.png` and
`docs-el_span-light.png`.

Check: `npx astro build` gives 44 pages with `dist/CNAME`; a link check
over `dist` finds 2,918 internal links, none broken and none under
`/open-ui/`.
