# Project website v0, 10 November 2026

A static website for the project, in `site/`, built with Astro 7.3.8 and
Starlight 0.42.8 and deployed to GitHub Pages
(`https://zhuowcui.github.io/open-ui/`) by `.github/workflows/site.yml`.
Plan workstream E (brand and web presence) and D (docs infrastructure). It
changes no engine, framework or components source.

## Direction

The first draft led with evidence: Chromium versions, census numbers, PR
links and a pixel-diff slider. The user rejected it as hard to read and not
about the product. This version is written for app developers choosing a
framework, after a study of Tauri, Flutter, Slint, Dioxus, Zed, shadcn/ui
and Bun. The home page answers, in order: what Open UI is, what its apps
look like, how it feels to write, what you get, and how to start. Fidelity
is one compact section, with the method on a short docs page.

## Screenshots

`openui-site-showcase` (`site/showcase`) renders each scene with
`HeadlessApp` at device scale 2, with the bundled Geist fonts, the shadcn
theme from `openui-components` and Chromium's Linux raster profile with
grayscale text antialiasing (LCD text shows color fringes once a browser
scales the image). Rendering twice gives byte-identical PNGs.

The comparison pair uses the harness's own profile on both sides:

| Side | Source | Command |
| --- | --- | --- |
| Open UI | `example-openui-light.png`: `site/showcase/src/example.rs`, `chromium_linux_lcd`, 440x220 at scale 2, on Windows | `powershell -File site\showcase\render.ps1 example-openui` |
| Chromium | `example-chromium-light.png`: `site/showcase/reference/example.html`, Chrome for Testing 147.0.7727.50 with the harness's real-font environment, in WSL | `python3 site/showcase/capture.py` |

10,819 of 387,200 pixels differ (2.8%), all inside the text's bounding box
(x 131 to 749, y 120 to 321 of 880x440); the box, border, badge and button
edges match. The text sits about one pixel higher in Open UI, the known
vertical placement difference. The home page says that text "can still land
a pixel off". This is a one-off visual comparison on the working branch,
not a harness measurement or evidence.

## What could not be rendered, and the workaround

- **`Card` and column flex.** A column flex container lays out each text
  item as if at its min-content width, so items grow tall (the components
  track's C4 finding). `Card` is a column flex box and its header is a grid
  with an `auto` column, so cards rendered far taller than shadcn/ui's. The
  scenes use block flow and row flex instead, with a bordered panel built
  from styled elements; the components page says why.
- **Icons in the app.** Open UI's SVG images support only static shapes and
  axis-aligned paths, so Lucide icons (curves) are not drawn in the
  screenshots; the dashboard uses text, counts and initials. The site's own
  icons are HTML.
- **No `flex` shorthand** and no `box-shadow` literal in `style:`; the
  scenes use `flex-grow`/`flex-basis` and no shadows.
